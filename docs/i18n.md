# i18n

The UI is English only, yet **all** UI text goes through
[Paraglide JS](https://paraglidejs.com), like in belegwerk-next.

## Convention

- Every text users see or that is read out to them lives in
  [`messages/en.json`](../messages/en.json): labels, `aria-label`, `title`,
  `placeholder`, toasts, error messages shown in the UI, window titles. This includes
  the shadcn/ui components under `src/ui/components/ui`.
- Components use the generated message functions:

  ```tsx
  import { m } from "@/paraglide/messages.js";

  <Button>{m.settings_apply()}</Button>;
  ```

- Keys are `snake_case`, prefixed with their area (`settings_`, `graph_`, …);
  reusable texts get `common_` (`common_cancel`).
- Parameters instead of concatenation: `"sync_paired": "Paired with {name}."` →
  `m.sync_paired({ name })`.
- Plurals use the message format's plural variants on `count`
  (e.g. `data_count_links` → "1 link" / "3 links").
- Not translated: CSS classes, `data-*` attributes, developer errors
  (`throw new Error(...)` that never reach the UI), keyboard shortcuts, and data from
  rekordbox or the backend.
- `src/business` returns data and codes, not UI text (lint rule). Errors the UI shows
  are coded (`ExchangeError`, `LinkError` in `business/errors.ts`, with parameters);
  `errorMessage()` in `src/ui/errors.ts` maps them to messages. Use it wherever an
  error is shown; other errors (e.g. from the Rust backend) keep their text.

## Setup

| File                                 | Purpose                                                 |
| ------------------------------------ | ------------------------------------------------------- |
| `messages/en.json`                   | All texts (single locale `en`)                          |
| `project.inlang/settings.json`       | inlang project: locales, message format plugin          |
| `project.inlang/paraglide.config.js` | Compiler options, shared by the Vite plugin and the CLI |
| `src/paraglide/`                     | Generated (git-ignored), do not edit                    |

`pnpm dev` / `pnpm build` compile the messages with the Vite plugin; `pnpm typecheck`
and `pnpm lint` run `pnpm i18n:compile` first, so a fresh checkout works too.
